# Evaluation and evidence

Run `python -m unittest discover -s tests -v` for deterministic helper/installation tests. `python -m reviewbench evaluate` retains the legacy synthetic AST fixture check; its output is not AI review accuracy.

The assistant harness uses `evaluate prepare --cases FILE --profile PROFILE --out PRIVATE_DIRECTORY` and `evaluate finalize --control CONTROL --responses DIRECTORY --out REPORT`. Cases contain captured changes, captured context and separately held judgments. See the skill evaluation reference for exact formats and optional adjudication.

Generic and persona packets share exact change/context digests. No-context removes surrounding evidence. No-style is included only for profiles that have style. Retrieval comparisons use separately captured bundles and are not attributed to persona effectiveness. Reviewer packets omit judgments; the control is scoring material and should not be supplied to reviewer sessions.

Use a fresh session per condition for stronger evidence. Record actual isolation; if sessions share authoring discussion or expected outcomes, do not call the run independent or held-out. Record model/host only when exposed, otherwise unknown. No cost, latency or model setting should be guessed.

Without grading input, finalization reports completeness and validated outputs. Optional human/assistant adjudication must account for each finding, link matches to expected issues, and explain rationale. Missing expected issues are reported. Partial runs cannot receive scores. Adjudicator independence is declared, not proven by the tool. Any stored response is a replay when reused.

The included two-profile worked example was generated by the current assistant using newly authored synthetic sources. It illustrates persona-dependent emphasis, not improved accuracy: the assistant authored the scenario and knows its intended concerns. Original benchmark results are excluded. Native platform validation and remaining live-provider checks are listed in validation.md.
